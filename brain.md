## 2. Locked Architectural Rules

All verified live in the code, not just asserted:

**The "golden rule"** — no element should be both (a) transformed by a parent's scroll animation and (b) the trigger/target of its own separate ScrollTrigger. Confirmed consistently followed. `src/components/home/HeroQuoteTransition.jsx` (lines ~42–73) has the canonical explanation as an inline comment: Quote.jsx used to be nested inside the Hero's pinned/transformed wrapper, and because ScrollTrigger caches trigger-element positions against a stable ancestor, that nesting caused a scroll "bounce back" bug once the wrapper's transform value diverged from its pre-scroll cached value. Fix: Quote now renders as an untransformed sibling. The comment names this as **the** fix for a specific historical bug — treat it as load-bearing, not decorative.

**Pinning uses `position: sticky`, not GSAP's `pin: true`.** Confirmed: `pin: true` does not appear anywhere in the actual animation code. The only hit for `pin:\s*true` in `src/` is inside a comment in `HeroQuoteTransition.jsx` explicitly documenting *why* it's avoided: GSAP's `pin: true` inserts a "pin-spacer" div into the live DOM outside React's fiber tree, which causes a `removeChild` crash if React later tries to unmount that subtree (e.g. `prefers-reduced-motion` flipping at runtime) because the DOM parent GSAP rewired no longer matches what React thinks it rendered under. Every pinned section (Hero, About, Projects, Instagram, Press, Footer, AboutHero, ProjectHero, ProjectsHero, Quote) uses sticky + scrub instead, which only ever touches inline styles, never DOM structure.

**Motion vocabulary standard:**
- `ease: "none"` on all `scrub: true` (scroll-tied) animations — confirmed consistent across Quote.jsx, Projects.jsx, About.jsx, ProjectsHero.jsx, ProjectHero.jsx, HeroQuoteTransition.jsx, AboutHero.jsx.
- `power3.out` on one-shot (`scrub: false`) reveals — confirmed as the dominant pattern (ContactContent, Press, Instagram, Footer, LegalContent, StudioDescription, FinalCTA, MeetFounders, IndiaMap, WhatWeBelieve, ProjectGallery).
- **Minor, deliberate exceptions found** (not stray — each is a different animation category, not a scroll reveal):
  - `Instagram.jsx` uses `power2.out` for its magnetic-cursor hover effect (a continuous pointer-follow interaction, not a scroll reveal).
  - `ProjectsGrid.jsx` uses `power2.out` for its one-shot card-grid reveal (`toggleActions: "play none none none"`) — this one *is* a one-shot reveal and technically deviates from the `power3.out` standard; worth normalizing if touching that file.
  - `Preloader.jsx` uses several eases (`power1.out`, `back.out(1.7)`, `power1.inOut`, `power2.in`, `power3.out`) — this is the boot-time intro sequence, not a scroll animation, so the scrub/one-shot rule doesn't apply to it by design.
  - `Press.jsx` line 212 uses `power3.out` for its drag-carousel snap — a one-shot settle, consistent with the standard.

**Spacing scale (8/16/24/32/48/64/96/128px):** Followed via Tailwind's default spacing utilities (`px-6`≈24px, `py-4`≈16px, `pt-16`≈64px, `gap-8`≈32px, etc.) throughout. Two small, deliberate off-scale exceptions found: `py-2.5` (10px) on `Button.jsx`'s `md` size and on the 404 page's CTA link, and `gap-3` (12px) in `ProjectGallery.jsx`'s row layout — both are fine-tuned UI-control paddings/gaps rather than section rhythm, so likely intentional, but flag if asked to audit strictly.

**JS-only:** Confirmed — `find src -iname "*.tsx" -o -iname "*.ts"` returns zero results. No `.ts`/`.tsx` files anywhere in `src/`.

**Shared hooks:** Both exist at `src/hooks/useReducedMotion.js` and `src/hooks/usePreloaderGate.js`.
- `useReducedMotion(initial = false)` — live-tracks `prefers-reduced-motion` via `matchMedia`, not just at mount. `Quote.jsx` deliberately passes `initial = true` (assume reduced until proven otherwise) to avoid a first-paint flash on its heavier pinned sequence; every other caller uses the default.
- `usePreloaderGate(setup, deps, enabled)` — defers a GSAP setup function until the `"preloader:complete"` event fires (or runs immediately if `window.__preloaderDone` is already true). Every ScrollTrigger-driven component needs this because trigger positions are measured against layout that only settles after the preloader intro finishes.
- **Used by (confirmed via grep, 21 files):** `AboutHero`, `StudioDescription`, `Footer`, `ProjectHero`, `ProjectsGrid`, `LegalContent`, `ContactContent`, `FinalCTA`, `Press`, `Projects` (home), `Instagram`, `Quote`, `ProjectsHero`, `ProjectVideo`, `About` (home), `ProjectGallery`, `HeroQuoteTransition`, `WhatWeBelieve`, `IndiaMap`, `MeetFounders`.
- **Not using them:** `Nav.jsx`, `ProjectDescriptionModal.jsx`, `Button.jsx`, `NextProjectLink.jsx`, `Preloader.jsx`, `SmoothScroll.jsx` — none of these run a ScrollTrigger-gated entrance (Nav is always-visible chrome, the modal opens on click not scroll, Button/NextProjectLink are presentational, Preloader runs before the gate event even exists, SmoothScroll just wraps Lenis). No undocumented gaps.

**Brand colors:**

- Ink — **`#2B2622` is authoritative**, defined in `globals.css`'s `:root` (`--foreground: #2b2622`) and used in 24 component files. `#2B2624` (the alternate mentioned in older notes) does **not** appear anywhere in the current codebase — treat it as stale/superseded.

- Sage `#5C6B47` — **zero occurrences** anywhere in `src/`. Not just underused — currently completely unused. Confirm with the client/Jitan whether it's still part of the active palette or has been dropped.

**Brand fonts:** Confirmed in `src/app/layout.js` — Agatho (`src/fonts/agatho-regular.otf`, headings only) loaded via `next/font/local`; Manrope loaded via `next/font/google`, applied as the body default (`font-manrope` on `<body>`). ## 4. Media Infrastructure

Project photos/videos are hosted on **Cloudinary**, not served from `public/images/projects/` in production. Cloud name comes from `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` in `.env.local` (currently `ypwxtxaj`; `.env.local` also holds the API key/secret used only by the upload script, never exposed client-side).

**Resolution flow (`src/lib/projects.js`):**
1. `scripts/photo-manifest.json` (checked into git) is the single source of truth for each project's photo list, natural sort order, and pixel width/height — **not** a live filesystem walk. This exists because the local WebP mirror was deleted once Cloudinary hosting was confirmed working end-to-end; the manifest was built right before that deletion and is now the only remaining record of gallery contents/order/layout. Confirmed current manifest: 7 project slugs, all with `hasVideo: false` except `the-modern-organic-home` (`hasVideo: true`).
2. `scripts/cloudinary-url-map.json` (checked into git, 206 entries) maps each local `public/images/...` path to its uploaded Cloudinary `secure_url`.
3. `toCloudinaryUrl(localSrc)` in `src/lib/projects.js` looks up that map and swaps the local path for the Cloudinary URL, falling back to the local path if no map entry exists yet.
4. `getAllProjects()` / `getProjectBySlug()` / `getNextProject()` combine the static `PROJECTS` roster (`src/data/projects.js`) with manifest-derived photos/video and Cloudinary URLs to build what each page renders. Galleries are grouped into rows (`groupGalleryRows`) — landscape photos get a full-width row each, portraits cluster up to 3-per-row.

**`media-source/`** holds raw/original backups (full-resolution project photography, `.mov` masters, `hero-video.mp4`). It's git-ignored (`/media-source/` in `.gitignore`, explicitly commented "raw/uncompressed source media awaiting compression — never deploy these") and never served.

Note: `public/images/projects/<slug>/` folders still exist **locally on disk** with real photos, but only 5 files under that whole tree are actually git-tracked (`.jpg`, `project-1/2/3.jpg` leftover placeholders, and one `video.mp4`) — the bulk of real project photography lives locally-only/untracked and is not what production serves; production/deployed builds rely entirely on the manifest + Cloudinary map, both of which *are* tracked.

**Upload/build scripts (`scripts/`):**
- `build-photo-manifest.js` — regenerates `photo-manifest.json` from `public/images/projects/` (uses `sharp` for dimensions). Must run before deleting any local WebP mirror.
- `upload-to-cloudinary.js` — signed uploads to Cloudinary's REST API via `curl` (not the Cloudinary SDK's own HTTP client — a documented TLS-renegotiation timeout issue on this network). Skips any file over 10MB (Cloudinary's Free-plan cap) rather than attempting and failing slowly. Run via `npm run upload:cloudinary` (aliases `node --env-file=.env.local scripts/upload-to-cloudinary.js`).
- `convert-to-webp.js` — WebP conversion step (pre-upload compression pass).

**Vercel requirement:** `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` must be set in the Vercel dashboard's environment variables, or production builds will fail to resolve any Cloudinary-hosted image/video URL. No `.vercel/` directory exists in this checkout, so this repo is not currently linked to a Vercel project via the CLI locally — confirm the dashboard-side project and its env vars directly with whoever set up the Vercel deployment (unconfirmed from code).

## 7. Workflow Notes for Future Sessions

- **Scroll-sequence bugs have a real history here.** The `HeroQuoteTransition.jsx` comments document a specific, previously-shipped "bounce back" bug caused by nesting a separately-triggered element inside a scroll-transformed ancestor (see the golden rule in §2), plus reasoning about a `removeChild` crash class tied to GSAP's `pin: true`. `AboutHero.jsx` was very recently ("Rebuild AboutHero: restore scroll-convergence sequence...") reworked specifically to fix photo alignment/scale/positioning bugs in its own pinned sequence. **When touching any pinned/scrubbed section, test forward AND backward scroll before considering a fix complete** — these bugs have historically only shown up on the reverse direction or on a second pass through the trigger.
- **Commit hygiene:** keep commits scoped to one logical change. The early commit history has several duplicate "Add Projects and ClientsGrid sections" commits in a row (5 of them) — a pattern to avoid repeating; prefer amending/rebasing locally before landing rather than stacking near-identical commit messages (though note the standing repo instruction to prefer new commits over `--amend` in normal day-to-day work — the duplicates above look like an early-setup anomaly, not the intended workflow).
- **Never commit raw/oversized media.** `media-source/` is git-ignored specifically to keep full-resolution originals and `.mov` masters out of the repo. Always compress to WebP (images) or a web-friendly H.264/H.265 MP4 (video) via the established `scripts/convert-to-webp.js` pipeline before anything reaches `public/` or gets uploaded to Cloudinary. Cloudinary's Free plan additionally hard-caps at 10MB/asset — `upload-to-cloudinary.js` already skips oversized files rather than failing slowly, but that means a file skipped for size will silently never appear on the live site until it's compressed and re-run.
